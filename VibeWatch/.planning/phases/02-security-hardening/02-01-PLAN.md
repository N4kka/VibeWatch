  <action>
    Create supabase/functions/cerebras-proxy/index.ts implementing the passthrough proxy. Follow the exact pattern from RESEARCH.md Pattern 1 and the verified code examples.

    Implementation requirements (all locked decisions):
    1. Import serve from 'https://deno.land/std@0.131.0/http/server.ts' (matches existing Edge Functions)
    2. Import createClient from 'https://esm.sh/@supabase/supabase-js@2'
    3. Read secrets via Deno.env.get(): SUPABASE_URL, SUPABASE_ANON_KEY, CEREBRAS_API_KEY, SUPABASE_SERVICE_ROLE_KEY
    4. CEREBRAS_ENDPOINT constant = 'https://api.cerebras.ai/v1/chat/completions'
    5. Require Authorization header — return 401 with JSON body { "error": "Missing Authorization header" } if absent
    6. Create per-request anon client with caller's Authorization header forwarded (JWT verification pattern)
    7. Call supabase.auth.getUser(token) where token = authHeader.replace('Bearer ', '') — return 401 { "error": "Invalid or expired session" } on failure
    8. Read full request body as text (req.text()) — forward as-is to Cerebras endpoint with server-side CEREBRAS_API_KEY in Authorization header
    9. Log token usage via adminSupabase (service role key) calling rpc('log_ai_token_usage', { p_user_id: user.id, p_tokens_consumed: tokensConsumed }) — wrap in try/catch, non-fatal
    10. Parse tokensConsumed from respJson?.usage?.total_tokens ?? 0 on a clone of the Cerebras response
    11. Return raw Cerebras response body with same status code and Content-Type: application/json
    12. Do NOT echo CEREBRAS_API_KEY in any error response body

    Error codes to use: 401 for auth failures, 500 for unexpected errors (generic message only).

    After creating the file, set the Edge Function secret before deploying:
    ```
    supabase secrets set CEREBRAS_API_KEY=<value-from-existing-Secrets.xcconfig>
    supabase secrets list  # verify CEREBRAS_API_KEY appears
    supabase functions deploy cerebras-proxy --no-verify-jwt
    ```
    Note: --no-verify-jwt disables Supabase's built-in JWT verification so the function can do its own verification (required for per-request client pattern). The function itself enforces auth.
